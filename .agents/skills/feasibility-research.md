# Investigación de Viabilidad de Proyectos

## Descripción
Habilidad para evaluar la viabilidad técnica, económica, operativa y temporal de un proyecto antes de comprometer recursos.

## Cuándo usarla
- Antes de iniciar un nuevo proyecto o producto
- Para evaluar si una idea es realizable
- Para decidir entre múltiples alternativas de proyecto
- Para justificar la inversión de recursos

## Herramientas
- **Análisis**: FODA, PESTEL, análisis de riesgos
- **Evaluación**: Matriz de viabilidad, scoring ponderado
- **Prototipos**: Proof of Concept (PoC), prototipos de baja fidelidad
- **Herramientas**: Notion, Miro, Excel/Google Sheets

## Dimensiones de viabilidad

### Viabilidad técnica
- ¿Existe la tecnología necesaria?
- ¿El equipo tiene las habilidades requeridas?
- ¿Se puede implementar en el tiempo disponible?
- ¿Hay dependencias técnicas críticas?

### Viabilidad económica
- ¿Cuál es el costo estimado (desarrollo, infraestructura, mantenimiento)?
- ¿Cuál es el retorno de inversión (ROI) esperado?
- ¿Hay presupuesto suficiente?
- ¿Cuál es el punto de equilibrio?

### Viabilidad operativa
- ¿El equipo puede mantener el proyecto a largo plazo?
- ¿Hay procesos y herramientas adecuados?
- ¿Se integra con sistemas existentes?
- ¿El personal puede usarlo efectivamente?

### Viabilidad temporal
- ¿Se puede entregar en el plazo requerido?
- ¿Hay hitos críticos o dependencias externas?
- ¿Cuál es el tiempo al mercado (time-to-market)?
- ¿Hay riesgos de retraso significativos?

### Viabilidad legal y regulatoria
- ¿Cumple con regulaciones aplicables?
- ¿Hay riesgos legales identificados?
- ¿Se necesitan permisos o licencias?
- ¿Hay implicaciones de propiedad intelectual?

## Receta

### 1. Definir el alcance del proyecto
- Objetivos claros y medibles
- Entregables esperados
- Restricciones conocidas (tiempo, presupuesto, recursos)
- Stakeholders identificados

### 2. Evaluar cada dimensión de viabilidad
- Recopilar información relevante
- Identificar riesgos y obstáculos
- Evaluar probabilidad de éxito
- Documentar supuestos y dependencias

### 3. Crear matriz de viabilidad
| Dimensión | Puntuación (1-5) | Peso | Puntuación ponderada | Riesgos |
|-----------|------------------|------|---------------------|---------|
| Técnica | | | | |
| Económica | | | | |
| Operativa | | | | |
| Temporal | | | | |
| Legal | | | | |

### 4. Identificar riesgos críticos
- Riesgos que podrían hacer fracasar el proyecto
- Probabilidad e impacto de cada riesgo
- Estrategias de mitigación
- Plan de contingencia

### 5. Formular recomendación
- **Verde**: Proceder con el proyecto (viabilidad alta)
- **Amarillo**: Proceder con precauciones (viabilidad media)
- **Rojo**: No proceder o replantear (viabilidad baja)

### 6. Documentar y comunicar
- Informe de viabilidad completo
- Recomendaciones y condiciones
- Próximos pasos sugeridos
- Presentación a stakeholders

## Errores típicos
- ❌ Evaluar solo la viabilidad técnica (ignorar económica, operativa, temporal)
- ❌ Ser excesivamente optimista en las estimaciones
- ❌ No identificar riesgos críticos
- ❌ No consultar con expertos cuando es necesario
- ❌ Ignorar el costo de mantenimiento a largo plazo
- ❌ No considerar el costo de oportunidad
- ❌ Confundir viabilidad con deseabilidad
